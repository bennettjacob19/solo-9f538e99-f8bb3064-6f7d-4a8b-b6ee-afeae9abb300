# 接收窗口排障工具

大文件上传卡住时，网管用本工具定位**接收窗口（通告窗口）何时用尽**：
上传发送端抓的以太网 PCAP，填写上传方向的 IPv4 TCP 四元组，即可得到
窗口用尽时段、分界帧，并可按任意时刻查询窗口余量与已发未确认字节数。

## 启动

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements.txt
python app.py          # http://localhost:8000
```

数据（SQLite）持久化在 `pcapdiag-data` 卷中；可用环境变量覆盖：
`DB_PATH`（数据库路径，默认 `/data/pcapdiag.db`）、`SECRET_KEY`。

## 使用

1. 首页上传发送端 PCAP（经典 pcap 格式，以太网链路层），并填写上传方向
   四元组：客户端 IP/端口 → 服务器 IP/端口。
2. 仅分析满足以下条件的连接，否则给出明确错误：
   - 捕获中含完整握手（SYN + SYN-ACK，用于确定 ISN 与 Window Scale）；
   - 单向传数据（服务器→客户端方向无载荷）；
   - 序号跨度 < 2 GiB。
3. 诊断页展示：
   - **窗口用尽时段**（余量 ≤ 0 的起止时刻、持续时长、最小余量）及
     **分界帧**（进入/退出用尽状态的帧）；
   - **按时刻查询**：输入 UTC 时刻或 epoch 秒，得到该时刻的窗口余量与
     已发未确认字节数；
   - **补传**：上传同次抓包的片段，自动合并并重算。

## 分析口径

- **窗口缩放**：仅当 SYN 与 SYN-ACK 都携带 WSCALE 选项时生效（RFC 7323），
  通告窗口按服务器（接收方）声明的 scale 左移，上限 14。
- **序号回绕**：序号统一换算为相对客户端 ISN 的偏移（mod 2³²）；
  跨度 < 2 GiB 保证映射无歧义。
- **窗口余量** = 通告窗口右沿 − max（累计确认点， 已发数据末端），
  其中右沿 = 累计确认点 + 缩放后的通告窗口。余量 ≤ 0 即窗口用尽。
- **已发未确认**：已发送字节区间的并集在累计确认点之后的部分，
  重传字节只计一次。
- **过时 ACK**（确认号小于当前累计确认点）直接丢弃：不回退累计确认点，
  也不更新窗口。

## 补传语义

- 片段沿用原抓包时间戳合并进时间线；
- 同一连接在**同一时间戳**上的**同一帧**（内容摘要相同）只计一次；
  若同一时间戳出现**不同帧**，整份补传被拒绝；
- 补入较早的帧后，受影响的后续诊断基于**已入库的帧**整体重算
  （无需重读旧 PCAP），诊断按版本原子切换——新结果就绪前、以及补传
  失败/被拒绝后，原诊断始终可查。

## 测试

```bash
python -m unittest discover -s tests -v
```

覆盖：窗口用尽时段与分界帧、时刻查询、序号回绕、重传去重、过时 ACK、
无握手/双向数据/跨度超限的拒绝、补传纠正、重复补传去重、冲突补传拒绝。

## 结构

- `app.py` — Flask 路由、上传/补传编排、版本化结果切换
- `analysis.py` — 窗口分析引擎（事件流、用尽时段）
- `pcaputil.py` — 经典 PCAP / 以太网 / IPv4 / TCP 纯 Python 解析
- `db.py` — SQLite 模式与连接管理（WAL）
- `tests/test_core.py` — 合成 PCAP 端到端测试
